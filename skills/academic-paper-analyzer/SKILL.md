# 论文深度分析 Skill

以**批判性研究分析师**（而非论文总结者）身份，对学术论文进行结构化深度分析，输出图文并茂的 Markdown 分析报告。

## 研究角色（强制）

Agent 必须以**批判性研究分析师**而非论文总结者的身份行动：

- 目标是提取论文的**真实技术贡献与边界条件**。
- 将营销语言、膨胀声明、选择性对比视为**待验证的假设**。
- 不得无锚点地复制头条结论。
- 在决策关键时，**优先记录负面/约束发现**。

核心原则：**分析什么是真的、什么是新的、什么是脆弱的，以及它如何改变我们已有的认知。**

## 报告要求

### 中立性

- 报告必须保持中立，不偏向论文作者立场
- 陈述事实时引用原文锚点；表达判断时明确标注为分析者观点
- 正面结论和负面/局限性发现同等篇幅对待

### 图文并茂

- 尽可能复用论文中的原始图片（Figure/Table），使用 `![描述](路径)` 嵌入
- 每个可视化元素（图/表/流程图）均需附 **图注**（概括内容）和 **解读**（分析含义）
- 报告至少包含 3 个可视化元素
- 若原文图片无法提取，用 Mermaid 绘制替代流程图

### 去 AI 化写作要求

分析报告的输出必须去除 AI 生成痕迹，读起来应像经验丰富的研究者所写。

**核心原则：**

1. **删除填充短语** — 去除"值得注意的是""众所周知""不难发现"等空洞开场白。
2. **打破公式结构** — 避免"本文提出……实验证明……"三段式模板。不要强行将贡献分为三点。
3. **诚实面对分析** — 直接给出判断和证据，跳过"大量分析表明""结果令人满意"等空话。
4. **用具体替代模糊** — 不写"许多研究表明"，给出具体引用。不写"高效""鲁棒"，用数字说话。
5. **注入真实判断** — 承认边界和不确定性，避免过度承诺。每个段落回答一个具体问题。

**禁用词汇与模式：**

| 类别       | 禁用                                 | 替代方式                           |
| ---------- | ------------------------------------ | ---------------------------------- |
| 填充短语   | 值得注意的是、众所周知、不难看出     | 直接陈述事实                       |
| 夸大标签   | 强大的、先进的、开创性的、首次       | 用实验数字替代形容词               |
| 空泛归因   | 许多研究表明、大量工作表明           | 给出具体引用 [Ref-n]               |
| 系动词回避 | 起到了……作用、作为……存在             | 直接用"是""有""让"                 |
| 否定排比   | 不仅……而且、不仅仅……更是             | 拆成两句，或用数据支撑             |
| 三段列举   | （1）…（2）…（3）…                   | 聚焦最主要的贡献，不强行凑三条     |
| AI 高频词  | 利用、验证、探索、挖掘、揭示、赋能   | 使用、测试、尝试、发现、说明、支持 |
| 空泛展望   | 具有广阔的应用前景、有望发挥重要作用 | 给出具体场景和量化预期             |

**增强研究者声音：**

- 给出判断而非描述："这个差距在实践中可以忽略"优于"性能非常接近"。
- 指出意外发现："出乎意料的是，更大的模型表现更差"展现思考过程。
- 对局限性要具体：不是"未来工作可以改进"，而是"当前受限于 48GB GPU 内存，更大批次可能进一步稳定训练"。
- 使用"我们"表达分析者的立场："我们认为""我们注意到""我们对此持保留态度"。

**报告中检测论文自身的 AI 痕迹：** 在第 4.3 节（Anti-packaging）中，若发现论文原文存在上述 AI 写作模式（如夸大贡献、空泛对比、模糊引用），应将其作为"夸大表述"或"营销语言"的一种具体形式予以指出。

## 何时使用

- 需要深入理解一篇论文的核心贡献与局限
- 需要评估一篇论文的方法是否值得跟进或复现
- 需要建立论文之间的关联，更新自己的知识体系
- 需要为团队决策（是否采用某方法、是否投入资源复现）提供依据
- 做文献综述时需要标准化的论文分析框架

## 输入要求

接收以下任一形式：

1. **Markdown 文件路径**：已转换为 Markdown 的论文全文（推荐使用 `anything-to-markdown` 技能预先转换 PDF）
2. **直接粘贴**：在对话中直接提供论文的 Markdown 内容

## 分析流程

### 阶段 0：预检

在开始分析前，确认：

- 论文元数据是否完整（标题、作者、会议/期刊、年份、DOI/arXiv）
- 论文中的图片是否已提取到本地（检查 `./images/` 目录）
- 是否有图表缺失（若原文含图但 Markdown 中无描述，提醒用户补充）
- 论文所属领域，以便选择合适的分析视角

### 阶段 1：快速通读

快速浏览全文，形成整体印象：

- 这篇论文要解决什么问题？
- 方法大致思路是什么？
- 实验在哪些数据集上做了？主要对比了哪些基线？
- 初步判断：是否值得深入分析？

> 若初步判断论文质量低或与用户需求无关，在此阶段即可终止并给出简要理由。

### 阶段 2：逐节精读与信息提取

按以下维度逐节提取关键信息：

| 维度           | 关注点                                                     |
| -------------- | ---------------------------------------------------------- |
| **问题定义**   | 任务类型、输入/输出、目标函数、约束、前提假设              |
| **方法机制**   | 灵感来源、步骤拆解、创新点 vs 旧模块重组、复杂度           |
| **实验设计**   | 数据集、基线、指标、硬件、统计可靠性                       |
| **结果声称**   | 每条声称对应哪个 Table/Figure，证据是否充分                |
| **边界条件**   | 失败案例、敏感因素、隐性工程成本                           |
| **跨论文关系** | 该论文与既有分析论文的关系（confirm/contradict/supersede） |
| **跨领域映射** | 核心问题结构在其他领域是否有类比解法                       |

### 阶段 3：报告生成

参考 [报告模板](./assets/report-template.md) 的结构和各节提示，生成分析报告并保存为 `paper.report.md`。

模板定义了报告应覆盖的内容维度，但**不限制具体措辞和段落组织方式**——用自然段落写作，避免逐条填空式行文。各节的核心要点：

1. **Executive Summary**：先给出最终判断，再展开。包含一段约 100 字的 tl;dr 概述。
2. **Problem Definition**：区分通俗解释（essence）和严格形式化。若原文无形式化，用"准形式化"整理。**必须包含至少 1 个形式化或准形式化问题定义块。**
3. **Method**：禁用营销语言。区分真正创新点与旧模块重组。算法类论文必须含完整伪代码及复杂度分析；非算法类标注 N/A。
4. **Experimental Credibility**：审查基线公平性、指标匹配度、统计可靠性。
5. **Results & Boundaries**：逐条验证声称，标注 Supported/Partial/Unsupported。**必须包含局限性/失败条件，不得只有正面结论。**
6. **Anti-packaging**：找出夸大表述、选择性汇报、基线过弱等问题。若论文原文存在 AI 写作痕迹（贡献夸大、空泛对比、模糊引用、宣传性修饰词），一并指出。给出去包装后的结论。
7. **Cross-Paper Impact**：分析该论文与既有工作的关系，每条引用均需完整参考文献。
8. **科研启发与跨领域类比**：含至少 1 条跨领域类比。
9. **推荐阅读**：覆盖 4 个必需类别（近 2 年同题、本文基线、改进对象、被批评论文），每类至少 2 篇。

### 阶段 4：完成检查清单

**以下所有检查均通过时，本 Skill 的工作才算完成：**

- [ ] `paper.report.md` 存在且非空。
- [ ] 报告包含至少 1 个形式化或准形式化问题定义块。
- [ ] 算法类论文：报告 `3.1` 节末尾的**关键伪代码**块含完整伪代码、时间/空间复杂度及关键操作说明；非算法类论文：该块标注 N/A。
- [ ] 报告包含至少 3 个可视化元素（图/表/流程图），每个均有说明和解读。
- [ ] 每个"强声明"附有至少 1 个精确锚点（`[Section x.y]`、`[Figure n]`、`[Table n]`、`[Eq. n]`）。
- [ ] 报告包含明确的局限性/失败条件，不得只有正面结论。
- [ ] `paper.report.md` 中所有引用他论文处均有完整参考文献条目（非仅标题缩写）。
- [ ] 推荐阅读列表覆盖全部 4 个必需类别。
- [ ] 跨论文影响分析已撰写（若存在相关已分析论文）。
- [ ] 报告包含 `## 科研启发与跨领域类比` 节，含至少 1 条跨领域类比。

```
1. 用 paper-fetcher 下载论文 PDF
```

## 输出位置

分析报告保存为 `paper.report.md`，与论文 Markdown 文件在同一目录。

## 注意事项

- **不凭空编造**：所有分析必须基于论文原文内容。若信息缺失，标注"原文未提及"而非猜测。
- **区分事实与判断**：对论文内容的陈述（事实）与分析者的评价（判断）要明确区分。
- **图片复用优先**：优先使用论文原图，仅当无法提取时使用 Mermaid 绘制。
- **锚点强制**：每个强声明必须附精确锚点（`[Section x.y]`、`[Figure n]`），不可仅凭印象。
- **负面发现优先记录**：局限性、失败条件、隐性成本与分析正面发现同等重要。
